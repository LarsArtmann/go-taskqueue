Split the store backends out of internal/queue

The one module whose depth score is wrong: a 182-LOC contract dragging 2,948 LOC of sqlite and postgres implementations — and both heavy dependency trees — through every contract import.

Round 1 (ADR-0011) split the library core; this round refines its one too-coarse module. internal/queue currently mixes mechanism (the Store contract, 182 LOC, stdlib + task + journal only) with two policies (SQLite 1,614 LOC with modernc.org/sqlite; Postgres 1,334 LOC with pgx). The import graph already separates them: webui, httpapi, harvest, review, status, worker use only contract symbols, while backend symbols appear in cmd/tq, examples, and test fixtures — and PostgresStore has zero production importers (CLI store wiring is a documented ROADMAP item). Today, importing the contract compiles both dependency trees for everyone.

Proposal

Three modules: internal/queue (contract + shared watermark entry type; deps: task, journal), internal/queue/sqlite (deps: queue, task, journal, modernc.org/sqlite), internal/queue/postgres (deps: queue, task, journal, pgx/v5). Types rename to the database/sql driver convention: SQLiteStore→sqlite.Store, OpenSQLite→sqlite.Open (same for postgres). Mirrored conformance suites travel with their backends — the repo already embraces mirroring as the conformance contract (ADR-0007), so no shared-suite module is needed.

03DAG & naming

New edges all point downward (backends → contract → task, journal). Naming follows the stdlib database/sql driver convention — package sqlite/postgres, concrete Store, constructor Open — eliminating the stutter of sqlite.SQLiteStore. The interface stays queue.Store; each backend gains a compile-time assertion var _ queue.Store = (*Store)(nil). ~57 rename sites across 17 files (cmd/tq, examples, root-package test fixtures) — internal code, no external consumers, clean rename with compiler-driven verification per file.
