03Cross-cutting findings

Version currency: one wave pending, one lib behind

8 of 9 adopted libraries sit on the latest tag (checked against the local checkouts on 2026-11-08). The exceptions: go-cqrs-lite has a four-module wave pending (metaengine v4.20.0→v4.23.0, sqliteengine v4.6.0→v4.8.0, system v4.16.0→v4.18.0 with AggregateFn SQL-injection hardening, id v4.7.4→v4.7.5) and go-datastar is one minor behind (v0.6.x→v0.7.0, static v0.6.1→v0.7.0). The depsweep sweeper is the designed vehicle for both.

Low scores are mostly deliberate seams, not neglect

go-error-family (13), go-datastar (17) and go-health (32) each hold a small, deliberate seam: one dead-letter gate, one static-JS submodule, one wire schema next to a hand-rolled prober (upstream's classifier cannot express tq's per-check warns — a severity-override design doc names go-taskqueue). Their recommendations are surgical swaps, not migrations.

The not-invented-here boundaries held

Every KEEP OUT cites an ADR or a test-pinned existing seam: internal/retryx, runactor, the stdlib-flag CLI, journal DedupKey, the no-store API posture. No rejected library was found to already have a hand-rolled duplicate in the repo that should have been the library all along.

Two prior deep-dives superseded

docs/research/2026-10-05_go-cqrs-lite-metaengine-system-deep-dive.html and docs/research/2026-09-14_templ-components-deep-dive.html are superseded by go-cqrs-lite.md and templ-components.md (narrower + newer wins). templ-components moved 64→78 since September; every high-impact cqrs-lite gap from October has since landed.
