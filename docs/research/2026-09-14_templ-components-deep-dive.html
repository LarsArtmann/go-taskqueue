00Summary

The dashboard's aesthetic identity is not the problem — the "ledger & lamp" theming is a textbook execution of the library's theme-bridge recipe, and every custom surface is a documented, test-pinned decision. The problem is interaction state versus live updates: every journal tick re-renders and swaps all five dashboard fragments, and that swap destroys whatever the operator was doing — typing in the search box, filling in a cancel-reason form, reading an expanded error cell. On a busy dogfood pool, ticks arrive every few seconds.

On the library side, the audit found one critical gap, two places where tq hand-rolls what the library already ships (sortable table headers, relative-time auto-refresh, pagination), and a handful of free wins (CopyButton, ListNote). Nothing found requires a library change; the biggest fix is roughly ten lines in app.js.

The bottom line Adopt what already ships: a swap-guard in the SSE client (fixes the state clobbering), Table.TypedHeaders sort links (the handler already parses ?sort= — only the UI is missing), and display.RelativeTime to delete the hand-rolled age ticker. Defer the htmx question (auto-submit filter bar) until the swap-guard lands; it changes what "apply" needs to be.

Method: full read of the library repo at head (v1.17.0, AGENTS.md 383 lines, 39 ADRs, 35 recipes), component source deep-reads, then a capability-by-capability comparison against internal/webui at go-taskqueue master. Every finding cites file:line in both repos. Capability existence was verified against the pinned v1.16.0 tag, not just master.

01Findings

These are the issues that need attention, ordered by impact.

Critical · live swaps destroy operator state

Every journal tick clobbers typing, open forms, and expanded cells

internal/webui/handlers.go:339,395-396 · render.go:741-757 · static/app.js applyFragment · fragments.templ cancelAction/rescueAction

On every change notification the server re-renders all five dashboard fragments — including #frag-filters (the search input) and #frag-table — and streams each as a frag event (handlers.go:395-396). The client replaces innerHTML wholesale (applyFragment). Under an active pool this fires every few seconds, so: text typed into the search box but not yet submitted is reverted to the server's value; an open cancel/stop/rescue reason form (it lives inside a table row, fragments.templ:270-309) collapses mid-typing; an expanded error cell snaps shut; the settled-tasks fold resets; keyboard focus inside a swapped fragment drops to <body>. This is very likely the concrete "the UI sucks" experience.

...
for _, frag := range frags {
    if err := stream.SendJSON("frag", frag); err != nil {
Fix: a swap-guard in applyFragment (~10 lines), no library change Skip swapping a container while it contains(document.activeElement) or an open <details>/[data-expanded] (defer that fragment to the next quiet tick), and diff-skip re-rendering #frag-filters server-side unless the filter state changed. For fold persistence, the library's CollapsibleSection singleton (collapsible_section.templ:69-94) demonstrates the exact re-apply-after-swap pattern; mirror it for .tq-settled. The library's own recipe sums it up: "state flags ride data-* attributes read by the page controller" — the controller currently doesn't read them back after a swap.
RETRACTED same-day · audit error

Sort is parsed but has no UI — TypedHeaders is the exact shipped answer

Correction (2026-09-14 13:10, screenshot pass) The claim below is WRONG: taskHeaders (components.go:512) already builds Sortable + SortDirection + Href for prio/attempts/age — shipped 2026-09-12 (commit 6feaa7d, before this audit). The visible table headers carry working sort links. The audit inferred "no UI" from the filter bar's hidden input without reading the header builder — exactly the verify-before-claiming failure this report preaches. Retained below unedited for the record.
internal/webui/handlers.go:32-40 (allowlist) · fragments.templ FilterBar · library display/table.templ:13-44 (verified present in v1.16.0)

The handler allowlists six ?sort= values (age/priority/attempts × asc/desc) and the filter bar preserves it as a hidden input — but nothing renders it. The operator cannot sort the ledger at all. The library's TableHeader{Sortable, SortDirection, Href} renders server-side sort links with aria-sort and ↑/↓ indicators — pure links, no JS runtime needed, CSP-safe by construction.

Fix Emit each header's Href via the existing sortURL-style helper and set SortDirection from data.Filter.Sort. Works unchanged with the hand-rendered Body slot — sorting is a header-level feature. Roughly an hour, pure operator win.
High · duplicate work

Hand-rolled age ticker reimplements RelativeTime (AutoRefresh)

internal/webui/static/app.js:28-45 (fmtAge/tickAges/data-age) · library display/shared.go:190-215 · display/relative_time.templ (verified in v1.16.0)

tq ships its own live relative ages: data-age epoch attributes, a fmtAge formatter, a 30-second setInterval. The library ships the same capability: RelativeTimeProps{Time, Now} renders <time datetime> with a title tooltip, and its AutoRefresh singleton re-queries time[data-tc-relative] on every tick — meaning it keeps working across tq's raw-SSE innerHTML swaps without any htmx dependency. The library version also adds i18n (Intl.RelativeTimeFormat) and correct screen-reader semantics.

Fix, with one honest tradeoff Adopt RelativeTime for the detail page's created/updated rows and the fact feed timestamps (exact fit) and delete the duplicated client code. The task table's compact band ("3m", "2d") is a deliberate density choice — either keep the short form there or accept the longer "3 minutes ago". Note components.go:134 factLines is already dead code (LSP-confirmed unused) from this same hand-rolled area — delete it in the same change.
Medium · shipped feature unused

Prev/next-only pager where navigation.Pagination ships page numbers

internal/webui/fragments.templ taskPager:170-195 · library navigation/pagination.templ (verified in v1.16.0)

The hand-rolled pager offers only ← prev / next →. The library's Pagination adds numbered pages with ellipsis, rel attributes, mobile/desktop responsive rows, and container awareness — all rendered as pure links from BaseURL + QueryParam, so it composes with tq's URL-carried filter state with zero JS.

Fix Replace taskPager with Pagination{BaseURL: "/", QueryParam: "page"}; the existing filter params are already carried by pageHref's URL building — keep that helper for BaseURL. The matching-count line can stay alongside it.
Medium · decision point

Filter apply forces a full page reload; FilterInput/recipe show the lighter path

internal/webui/fragments.templ FilterBar:473-525 · components.go:291-293 (HTMX deliberately stripped) · library forms/filter_input.templ, docs/recipes/horizontal-filter-bar.md

Applying a filter is a full GET: the page repaints and the SSE stream reconnects. The library's FilterInput (300 ms debounce, auto-submit, <search> landmark, no-JS fallback) and the horizontal-filter-bar recipe's hx-get + hx-target + hx-push-url pattern solve this — but require the htmx runtime that tq explicitly strips in dashboardProps (it's still embedded in layout.Base via //go:embed, so re-enabling is a one-liner with zero extra requests). The recipe's footgun #1 (silent query-param drop) is already handled correctly by tq's hidden inputs.

Fix: sequence it after issue 1 Once the swap-guard exists, either (a) re-enable embedded htmx and wire the filter form to target #frag-table only, or (b) add a ~15-line fetch-submit to app.js with history.pushState. Decision hinges on whether htmx returns for other interactions too — worth one deliberate ADR note rather than an ad-hoc choice.
Low · free wins

Small duplications and missed conveniences

fragments.templ:56-81, 69-79 · task detail page · library display/copy_button.templ, display/list_note.templ, errorpage/ module
  • ListNote: the "+N more projects" chip in StatusCards is a hand-rolled ListNote ("Showing N of M", role="status").
  • CopyButton: the status-report card calls its path "copyable code" — nothing copies it. CSP-safe CopyButton with "Copied!" feedback fits there, on task IDs, and on payload panes.
  • errorpage module: tq's chrome-consistent 404 is better than the generic one for this UI, but errorpage.WriteError would give 500s the same treatment; today they are bare.
  • Icons: 4 of 102 used (empty states). The apply button, clear-all link and DLQ heading are icon candidates.
  • TableRow.Href: whole-row click + keyboard navigation exists upstream, but only on the Rows path — tq's rich Body-slot rows can't adopt it without giving up badges/actions. An upstream Body-slot row-href hook is the only gap found that would need a library change.

04Visual pass — 2026-09-14 13:00-13:10

Confirmed worst visual bug

Chart y-axis labels render as an illegible vertical smear

library line_chart.go:123 lineChartMaxTicks=8 (private const, no prop) · tq passes Height: 120

Up to 8 tick labels are drawn into a 120px plot in every theme — overlapping on desktop, rotated into a solid bar on mobile. tq cannot fix this via props: no tick-count option is exposed. tq-side stopgap: raise Height. Real fix is upstream: tick thinning by plot height, or a MaxTicks prop (verify-before-filing applies before any upstream report).

Confirmed on capture

Board clips two of five columns with no scroll affordance

fragments.templ Board: 5 × w-64 (~1344px) inside the 2fr column (~880px)

DEAD and CANCELLED exist only off-screen; nothing hints they are reachable. Fix directions: scroll hint/fade, responsive column width, or full-width board when the task region is the page's focus.

Also confirmed

Smaller visual findings

  • Fact-rate y-domain 0-35 from one burst: the chart reads as empty space with a right-edge spike — domain compression or annotation needed.
  • Populated active table's last column (last error) clips at the card edge — scrollable via the library's overflow-x-auto wrapper, but no fade/scroll hint; with --allow-writes an actions column joins the clip-prone tail (the code comment knows: components.go "the table tail (age, error) is the clip-prone end").
  • Mobile 375px: charts (fixed Width: 560) clip their x-labels at both card edges.
  • Aside dead-ends below "browse the full journal"; board view leaves the main column mostly void.
  • DLQ is a wall of red when dead dominates: red text on tinted rows, mid-word truncation without ellipsis.
  • Detail page headline is the full 26-char ULID at 2xl — noise; CopyButton gap confirmed visually.
  • Tablet 768px is the best layout: single-column stack, everything fits, nothing clips.
  • What works: dark identity (bezel nowband, signal cyan, mono headings, terminal feed), detail-page hierarchy, live age ticker, retry-backoff readiness countdown, two-tier active/settled concept when populated.
