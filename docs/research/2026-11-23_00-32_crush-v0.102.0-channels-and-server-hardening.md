## Why crush v0.102.0 is worth reading

It is the release where Channels — tq's `tq mcp` Phase 2 transport — went from
source-verified-on-`main` to a shipped, documented feature, and where ~50
server-hardening fixes landed squarely on the routed-run surface (`-H` thin
clients, the shared server, the keeper). One change breaks tq's server-death
classifier outright (fail-on-drop), one invalidates the keeper comment's
keep-alive theory (idle = zero workspaces, not zero clients), and two remove
standing hazards (interrupted-run zombie burn; stdio-MCP cross-project cwd).

## Rejected / not applicable (so nobody re-litigates blind)

- **BYO prompts (`option prompt`, `--prompt` flag)**: tq's rails are baked into
  the prompt argv and the `.crushrc` managed block stays model+effort only;
  moving prompt content into crush prompt templates would make prompt-diffing
  daemon-invisible (AGENTS.md: prompt-content changes are dedup-invisible when
  daemon-folded). Recorded as considered-and-rejected, not a gap.
- **DNS-rebinding / cross-site TCP blocks**: tq's server surface is a unix
  socket; the HTTP-listener hardening is N/A.
- **Nerd fonts, KITT/Rosé Pine themes, queued-prompt pill, sudo/PAM, Ollama
  discover filter**: TUI-only, no pool interaction.
- **`channelTargetSession` viewed-session preference** (`internal/backend/channels.go` around line 114 at v0.102.0):
  matters only once Phase 2 pushes land; folding it into the pilot probe, not
  this note's actions.
