(that is the whole point of `tq api` vs the dashboard); making them sniff a
text/plain body for the two most common non-happy responses was an accident of
`http.Error` convenience, not a design position. Both auth-plane responses now
flow through the same `writeError` seam every handler error already used:

- **401** (internal/httpapi/httpapi.go:115-116): body
  `{"error":"unauthorized","fix":"present a valid bearer token (Authorization: Bearer <token> or ?token=<token>)"}`;

- **429** (internal/httpapi/httpapi.go:101-107): body carries the full
  lockout message in `error` plus a wait-out hint in `fix`; the
  `Retry-After` header is untouched (machines should honor the header; the
  body is now parseable regardless).

`nosniff` remains set on EVERY response including the auth plane (set before
the branch), and `writeJSON` sets `Content-Type: application/json` — so the
http.Error side effects (text/plain + its own nosniff) are fully replaced.
Tests assert only status codes, so no test churn was needed — which is also
the honest gap (§b1).
