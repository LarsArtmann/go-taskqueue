## e) WHAT WE SHOULD IMPROVE

1. `anchorLooksPositional` is heuristic and asymmetric: a genuinely numeric code
   anchor ("42", "3.14") would be REJECTED as positional (false positive), and
   unusual positional phrasings ("around line 40") pass (false negative). A
   shorter, mechanical rule ("anchor must contain ≥1 letter") might be strictly
   better than pattern-matching.
2. The pre-flight error should ideally tell the reviewer HOW to comply (it does:
   "quote the verbatim text") — but the retry re-runs the full review prompt;
   a cheap improvement is echoing the anchor rule at failure site in the output
   the model sees.
3. `mintFixes` trusts recorded findings verbatim; findings recorded BEFORE this
   hardening have no anchor and fix prompts degrade gracefully (anchor section
   omitted) — consider a backfill audit for pre-hardening review facts.
4. The webui finding card should render anchor (as quote) + commit sha (short);
   natural next UI pass.
5. Consider extending the same anchor discipline to `dlqfix` autopsy findings and
   the cqa bridge (both file findings today without anchors).
6. Daemon-committed code vs footer commit split is chronic for queue-attributed
   work; the amend maneuver or a footer-aware daemon remains the systemic fix.
