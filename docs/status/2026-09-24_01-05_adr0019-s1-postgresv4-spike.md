## a) WHAT SHIPPED

`internal/queue/postgresv4` — the postgres half of ADR-0019 §S1, mirroring the
sqlitev4 spike's division of labor (docs/status/2026-09-23_16-28_adr0019-s1-sqlitev4-conformance-divergence-report.md):

- **Engine-backed** (`go-cqrs-lite/queue/postgres/v4 v4.0.0`): Enqueue, Complete,
  Fail, FailPermanent, Heartbeat, Cancel, CancelRunning, CancelRequested,
  CancelOwned, MarkOrphaned, RescueDead, DismissDead, UpdatePendingPriority.
- **Adapter-side** (same database, own pgx handle): tq's ClaimDue with
  project-exclusivity (D24), Requeue with resume_closeout evidence, all reads,
  RecordAnswer/questions, AppendFact, watermarks, priority_scores cache,
  CountFacts/FactsSince/LastFacts, StatusCounts, ProjectCounts.
- **D1 parity carried over**: Complete clears `last_error` after the finalize
  (the 00-12 fix), same code shape as sqlitev4.
- The upstream postgres engine's DDL (ddl.go) stores the same shapes the
  adapter SQL expects (BIGINT unix-millis, TEXT statuses, BIGSERIAL fact seqs),
  so the companion handle reads the engine's own tasks/facts/deps/watermarks
  tables directly — no schema fork.

### Postgres-specific deltas (the only non-copy changes)

1. **`pgq` placeholder seam**: the shared adapter SQL stays in sqlite-style `?`
   form; one converter (`pgq`) rewrites top-level `?` to `$n` ordinals at six
   tiny exec/query wrappers. A pure `$n` rewrite of ~120 SQL sites was the
   error-prone alternative; the seam keeps the two spike adapters diffable.
2. **`MIN(a,b)` → `LEAST(a,b)`** in the aging ORDER BY (postgres has no
   two-arg MIN), and sqlite's `LIMIT -1` (no-limit) dropped — PG omits LIMIT.
3. **Per-test schema isolation**: the sqlite battery used a temp file per test;
   postgres gets a fresh `tqtest_<hex>` schema per test via `search_path`
   runtime param on both the engine pool and the companion handle, dropped
   cascade at cleanup — the parallel battery cannot see itself.
4. `scored_at` column is BIGINT (sqlite INTEGER millis would overflow in 2038
   as a PG 4-byte int).

## d) TOTALLY FUCKED UP

1. **`sed -i -n` truncated the freshly written adapter to one line** (the
   `-n` + single `p` expression was a dry-run pattern with `-i` applied).
   Recovered losslessly by re-deriving the file from sqlitev4 with one
   deterministic python transform — but the recovery silently re-applied ALL
   edits, which is also why the final file has no archaeology. Lesson:
   `sed -i` and `-n` never in the same invocation.
2. First `initdb` instance was left half-started after a port collision; the
   "is it running?" probe (psql refused) preceded the retry on a fresh port
   rather than a blind restart.
