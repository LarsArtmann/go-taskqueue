## a) Verdict

The "3x re-dispatch" was NOT harvest rewording, NOT a re-enqueue, and NOT the
14-01 reworded-duplicate class. It was the **retry ladder of ONE task**: a
single enqueue (fact seq 5293, dedup key `todo:bbfb950bc388b66b`, exactly one
task row) whose three verify failures requeued the same task id twice, spawning
three agent dispatches (attempts 1/2/3), each of which wrote its own
close-out/verify-window report — hence four reports (11-58 work + 12-01
close-out, 12-05, 12-11) against one id.

## c) Why every attempt failed: the known structurally-red gate

All three failures are the SAME deterministic dead-letter machine documented in
AGENTS.md (2026-09-21 §f4): the minted verify gate ends with
`test -z "$(gofmt -l .)"`, which walks the gitignored `vendor/` tree.
Reproduced first-hand at HEAD: `gofmt -l .` flags exactly **44 files, all under
`vendor/`** (third-party code); zero tracked files flagged. The verify
failure log (`~/.local/state/tq/logs/…verify-failure.log`, 19 lines) shows
every package `ok` and no failing test — the failure is the gofmt stage alone.

Each attempt DID complete its real work (row 179 was correctly closed by the
11-58 window; the later windows were honest verify-only re-checks that found
no delta) — then died at the broken gate, burned an attempt, and requeued.

## d) Root-cause chain

1. Enqueue → work completes, row closed → verify dies on vendor-gofmt.
2. Retry ladder re-dispatches the SAME id (by design).
3. Each re-dispatch re-runs the agent, which sees the DONE row, writes another
   duplicate close-out/verify-window report, dies at verify again.
4. 3/3 → dead letter. The DLQ is the human surface for the owner-only fix.

The multiplication class is therefore: **broken deterministic verify gate ×
attempt ladder × report-per-attempt** — not any enqueue-side duplication.

## e) Fix (owner-only, already tracked)

The fix is pinned in AGENTS.md: scope the gofmt stage to tracked files
(`gofmt -l $(git ls-files '*.go')`) in BOTH `.tq-verify` and the mint
template. Agents must never edit their own gate. The two dead tasks of this
class (000001a0bd9a…, 000001a0c124…) and this one stay dead until the owner
flips the gate; rescue is pointless while `gofmt -l .` still flags vendor/.
