## e) WHAT WE SHOULD IMPROVE

1. **Fixture decay is a silent class.** A fixture embedding a frozen
   past DATE keeps passing while silently changing which code path it
   exercises (here: reset-parse → 15-min fallback, since ~2026-09-12 —
   nothing failed, so nothing caught it). Rule going forward: any
   time-based fixture computes its timestamps at run time. Generalizable
   further: sweep for calendar-date literals in smoke scripts and
   testdata (§f3).
2. **The demonstrated-failure standard should extend to smokes**, not
   just check-* gates. Even when the true regression needs a code
   change, guards introduced FOR the smoke (like the window-too-short
   check) are cheaply provable with a doctored /tmp copy.
3. **Measure what you add to a gate's runtime.** Sleeps added to
   ci-local deserve a wall-time number in the close-out, same as gate
   green/red.
4. **The daemon-race protocol works; the attribution protocol doesn't.**
   Four instances of footer-on-docs-only-commit is not a diligence
   problem — it is the auto-commit daemon structurally winning the race
   for any content it sees first. Only a protocol change fixes it (§g1).
5. **Reading the source row's actual f-number mapping paid off**: the
   TODO row's "f29-f38/f43-f48" look like findings but are §f list items
   of the 16-00 report. Trusting the row text without locating the
   source would have sent the lap hunting for nonexistent finding IDs.
