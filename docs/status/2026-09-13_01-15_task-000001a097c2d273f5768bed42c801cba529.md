1. **Root cause, source-verified.** The per-collect budget was the whole story:
   every iteration opens a fresh SSE collect whose budget must cover TCP connect →
   handler schedule → hub subscribe → `loadSnapshot` (SQLite query) → templ render →
   first flush. `ssetest.CollectWithTimeout` fatals when ZERO events land inside the
   budget (`go-sse/ssetest/collect.go:146-149` via `ReadNEvents`, which treats a
   scanner error with 0 collected events as fatal and events>0 as clean close,
   `reader.go:99-105`); the request path fatals identically if response headers are
   late (`collect.go:191-194`). The 30ms budget was a hang guard, not the pin — the
   pin (crash fix: heartbeat goroutine stopped before handler exit) only needs
   disconnects with heartbeat ticks in flight (5ms tick ⇒ dense per stream).
2. **Reproduction with the exact reported signature.** Baseline isolated `-count=10
   -race`: 10/10 green (10.7s — matches "green isolated"). Under background suite

   in, first iteration), 9/10 green — p(miss) ≈ 6-7% per connect under load,
   consistent with 3-4/4 suite runs catching ≥1 miss in 31 collects.
3. **Fix, smallest correct change.** `internal/webui/webui_test.go`: `collectBudget`
   30ms → 250ms (~10x headroom over the observed loaded tail; ~50 heartbeat ticks

   - final collect (wall ~2.5s/run vs 0.93s — declared tradeoff, keeps the crash-fix
