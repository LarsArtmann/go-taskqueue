## e) WHAT WE SHOULD IMPROVE

1. **Agent habit: commit immediately after the verify gate.** The daemon
   commits on a heuristic sweep; any agent that leaves verified work
   uncommitted while writing prose is racing it. The amend recovery works
   but shouldn't be needed.
2. **The daemon bypasses pre-commit hooks.** Evidence: two reports from
   08:39 and 08:47 landed UNINDEXED within the hour (the hook
   `check-status-index.sh` exists precisely because unindexed reports go
   missing; it demonstrably didn't run on those commits). Either the
   daemon's commit path should run the repo checks, or agents must treat
   hooks as never-guaranteed and run checks themselves before committing.
3. **Enforce the TQ_BIN convention mechanically.** A ~10-line check (same
   style as `check-todo-list.sh`) that every `scripts/smoke/*.sh` which
   builds tq honors `TQ_BIN` — grep for the variable, fail the gate if a
   smoke builds unconditionally. multi-repo.sh is proof the convention
   rots silently when it's prose-only.
4. **Harvest verification should include reading the prescribed command.**
   "Verified" items that say `run X` need X's mechanism checked, not just
   X's existence. One `rg TQ_BIN scripts/smoke/multi-repo.sh` at harvest
   time would have caught f35.
5. **Smokes should log the binary identity.** Print `tq version` (and the
   binary path) at smoke start when TQ_BIN is set — makes every future
   "smoked the release artifact" claim auditable from the log alone
   instead of living in reports.
6. **Release verification breadth:** scripts/release.sh:92 smokes webui
   with the TQ_BIN binary, but the multi-repo smoke — pools, leases, dedup,
   the core product claim — isn't in release verification. Candidate
   addition (owner latency call, see §g1).
7. **multi-repo.sh failure forensics:** on FAIL it tails only 8 lines of
   each pool log and, with `SMOKE_KEEP=0`, deletes the workdir including
   those logs. Keep-on-fail (or a bigger tail) would make CI failures
   debuggable from the log alone.
