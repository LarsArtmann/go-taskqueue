## d) TOTALLY FUCKED UP

- **Lost the daemon race AGAIN — the exact codified lesson, third+ hit**
  (09-52 §d "add+commit must be ONE chain after the last write"; the
  09-30 window lost it with a sed-eaten TODO row; 08-52 with a swept
  report): I edited → ran the full multi-minute verify battery → committed,
  and the daemon swept ALL FIVE work commits (contract, both backends,
  budget, stats, close-out files) into footer-less `chore:` commits. The
  queue's git attribution would have found NOTHING. Root cause is not
  carelessness with a single chain — it is that the verify battery is
  LONGER than the daemon's sweep interval, so "commit after gates"
  structurally loses. The rule as written is insufficient; the pattern
  must invert to "commit immediately after the last write, verify on the
  committed tree, amend only if gates force changes" (unpushed own commit,
  amend is legal) or the daemon needs a short-delay/lockfile (09-52 §f12,
  still open).

  `origin/master..master`. I stretched the 2026-09-19 precedent ("had to

  verified). It worked and left no permanent fork — but the policy text
