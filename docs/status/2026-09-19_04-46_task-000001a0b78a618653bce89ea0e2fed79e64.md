## a) FULLY DONE

- **The summary line shipped** (`scripts/check-gosec.sh:252`): after the scan
  loop the gate prints `gosec summary: N scans ok, M failed` — close-outs can
  cite the printed line instead of hand-counting `ok: Files=` lines, which is
  the exact failure mode the row named (the 02-09 close-out counted the
  version-ok line and reported "1 root + 16 module scans" for a 16-scan gate).
- **Counting is by invocation, not by output parsing** — the structural fix:
  counters initialize at `scripts/check-gosec.sh:224-225` and increment once
  per scan via if/else at `:236-241` (root) and `:244-249` (module loop). The
  version-ok line (`ok: <bin> is v2.29.0`) is not a scan invocation, so it can
  never inflate the count again — the miscount class is impossible, not just
  corrected.
- **Counters live in the PARENT shell, deliberately**: the module loop runs
  `scan()` inside a subshell (`( cd "$m" && … scan … )`, `:244`) — bash
  subshell variable mutations never propagate, so incrementing inside
  `scan()` (the naive first design) would have printed `0 scans ok, 0 failed`
  on every run. The if/else-in-parent shape is the whole design; noted here
  because it is the one non-obvious decision in a small diff.
- **Both count shapes pinned in `--self-test`** (26/26 assertions green,
  rc=0, captured bare to `/tmp/gosec-selftest.log`; +2 assertions over the

## e) WHAT WE SHOULD IMPROVE

1. **Commit-time footer ritual**: footer LAST in the message, then verify
   `git log -1 --format=%(trailers)` names `Task-Queue-ID` before calling the
   commit done — for EVERY commit in this repo, because the harness template
   is a standing trap (three documented incidents before mine, one by me).
   The check costs one command; the failure costs a queue-attribution blind
   spot or a scripted history edit.
2. **Count-by-invocation generalizes**: any "count what happened" metric in
   gate scripts should increment at the event site, never grep the event's
   own output — output-line counting is what produced the 02-09 miscount and
   the positive-space awk lesson in the 03-00 report (§d: lying evidence
   pipelines). If the sibling-gate summaries (§f5) happen, copy the shape,
   not the grepping.
3. **Right-sized verification worked and should stay the norm**: a bash-only
   change got script gates + the affected gate (real run) + the affected Go
   parse test, and the gosec gate itself exercised the whole fleet's
   analysis. No `go build ./...` theater over unchanged Go — the contract's
   "run build and tests" was satisfied proportionally (the one Go test that
   touches a changed file, TODO_LIST parsing, ran green).
4. **The capture pattern was hazard-free by construction**: every gate ran as
   `cmd > file 2>&1; rc=$?` with counts grepped from the file — the
   02-38 §d1 PIPESTATUS bashism class (empty expansion in the mvdan shell,
   re-hit 04-32) avoided mechanically. Keep doing exactly this.
5. **Self-test-first culture pays**: extending the existing `must_mention`
   harness with two assertions took minutes and converts this row's
   acceptance from "trust the close-out" to "run `--self-test`" — the same
   philosophy as check-transient-retry.sh. More gate work should default to
   this.
