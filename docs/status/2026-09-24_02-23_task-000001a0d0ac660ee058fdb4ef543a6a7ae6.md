## d) TOTALLY FUCKED UP

   first battery used `test -z "$(gofmt -l .)" && echo "gofmt clean"` —

   visible until a second explicit `gofmt -l .` run. This is the
   PIPESTATUS-hazard class in disguise: a chained assertion whose

## e) WHAT WE SHOULD IMPROVE

1. **Verify-battery helper**: one script that runs the standard
   battery and PRINTS per-gate evidence lines (name, command, rc, key
   output), so windows stop hand-rolling `rc=$?` chains — kills the
   d1/d2 class at the root. Candidate: `scripts/verify-battery.sh`.
2. **DONE-row verify depth standard**: a verify window on a shipped row
   should cite (a) the row, (b) the prior report, AND (c) one fresh
   grep/read of the artifact itself (test names, package doc) proving
   the claimed surface exists — not just exit codes. Codify in
   CONTRIBUTING or the session-start output.
3. **First-response close-out**: windows should write the self-review
   in the same session that does the work, not on explicit request —
   three same-day recurrences now (01-40 §d, this window).
4. **Stale §d forward-reference**: when a close-out follows the verify
   report within the hour, the close-out should say so explicitly
   (this report does; done here as the fix, the pattern needs a name).
5. **gofmt vendor exclusion**: make the documented
   `git ls-files '*.go'`-scoped gofmt invocation a tiny script and
   reference it from session ritual so root `gofmt -l .` stops
   producing 44 false hits per window.
6. **Replay rehearsal before cutover**: row 42 (owner-run cutover)
   should require one rehearsed end-to-end replay run against a seeded
   scratch DB first — currently the tool's main path has zero recorded
   executions.
7. **CI-state glance**: add `gh run list --limit 1` (or
   `scripts/check-ci.sh`) to the verify-window battery — a local-green
   claim without master state is half a claim.
