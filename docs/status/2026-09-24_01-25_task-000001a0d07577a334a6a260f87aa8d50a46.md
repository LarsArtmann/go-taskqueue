## e) WHAT WE SHOULD IMPROVE

1. **One-command scratch postgres.** The initdb/pg_ctl/DSN dance should be
   a script (`scripts/dev-scratch-postgres.sh` — start on a free port under
   /tmp, print the TQ_TEST_POSTGRES DSN, `--stop` subcommand, rc-checked).
   Every future TQ_TEST_POSTGRES window rediscovers this. It also makes CI
   -optional local live-postgres runs a 10-second affair instead of an
   auth archaeology dig.
2. **Grep prior reports for the ENV RECIPE, not just the task**: turn-1
   addition #1 says grep for the task id; for env-gated suites the second
   grep should be for the env var name (`rg TQ_TEST_POSTGRES docs/status/`)
   to inherit the working DSN recipe.
3. **Verify-window report compression**: for a repeat verify window with
   zero new deltas, a short-form report (≤10 lines: HEAD, gates rc, delta
   or "none, reason", pointers to the canonical prior report) should be
   legitimate. The 01-18/01-24 full-format reports are 90% carried-forward
   text — the index row already carries the summary.
4. **Stop-output rc capture habit**: any command whose failure mode matters
   (`pg_ctl stop`, `trash`) gets its rc read, period — same rule as gates.
   The §d4 stray-postmaster risk is the concrete instance.
5. **The DONE-row re-dispatch loop needs the owner ruling** (§g1) — until
   it lands, agents should treat "third+ dispatch on a DONE row" as a
   signal to run the SHORT battery and file the SHORTEST legal report, not
   to keep producing closeout-grade prose.
6. **Master-CI check belongs in the verify-window minimum battery** — it's
   one cheap call and ci-local's own gate starts with it.
