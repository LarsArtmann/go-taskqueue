## e) What could be improved

- **Wave-gap gate**: a devmod-CI check that cmd/tq floors cover the API
  its source uses would have caught this entire window's root cause at
  S4-landing time (the 18-29 report even flagged the RED-ON-CLEAN tidy as
  pre-existing).
- **Quiet-tree rule for tag cuts**: release.sh preconditions check a clean
  tree but not module-gate health; a pre-cut `check-go-mods.sh` invocation
  belongs in the ritual (or in release.sh before sub-tag cuts).
- **Directive-rewrite guard**: concurrent sessions run tidy with
  mismatched toolchains and rewrite `go 1.27.1`→`go 1.27`; the gate catches
  it post-hoc — a pre-commit check-go-mods leg (or GOTOOLCHAIN pin in the
  tidy path) would catch it at write time.
- **Rot-pins should print diffs**: "expected 55, got 57" should name the
  two flags (flag-set diff) for instant triage.
- BuildFlow's zero-pseudo-version preflight policy contradicts the repo's
  gate_gomod (real tags REQUIRED, `00010101` is a FAIL) — reconcile via
  BuildFlow config exclude or upstream fix; until then that preflight FAIL
  is noise for this repo.
- `go-mod-update` 15/16 historical failures: the counter should reset or
  annotate after a fix lands, or it keeps crying wolf.
