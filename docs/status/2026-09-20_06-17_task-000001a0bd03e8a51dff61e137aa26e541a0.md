## e) WHAT WE SHOULD IMPROVE

1. **Commit timing discipline**: with explicit commit authorization, the
   commit should land immediately after the last content edit; gates run
   after (they were all green anyway — nothing was at risk, only the daemon
   race was).
2. **The self-test's clean-run assertion depends on an exact baselined
   count** (currently 2). A future edit to the fixture that adds a citing
   line must update the count; acceptable for a 60-line fixture, but the
   failure output does name the expected vs actual, so drift is diagnosable.
3. **Spaced arrows (`old → new`) are not escaped by the gate** — only the
   adjacent `old→new` form matches the regex. AGENTS.md's sanctioned fork
   notes use the adjacent form today, so the gate is correct for current
   reality, but a spaced fork record in a future report will DEAD-SHA-fail.
   Either the docs convention should state "adjacent arrows only" explicitly
   or the regex should allow whitespace. Candidate backlog row (f2).
4. **`in_baseline` is O(baseline lines) per token** — fine at 28 rows, was
   already fine at 242; no action needed, just recording that the extraction
   did not change performance characteristics.
5. The gate counts baselined hits but the count is invisible on a FAILING
   run (the `ok` line only prints on rc=0); a failing run with a MIX of
   baselined and new hits reports only the new ones. Harmless (failure is
   the signal), cosmetic only.
