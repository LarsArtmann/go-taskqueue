## e) WHAT WE SHOULD IMPROVE

1. **Baseline-first discipline for report scripts**: any script whose output is a
   count must be run BEFORE the edit and the counts used as the acceptance oracle
   after. I did this once (68-dead baseline) and it caught the §d1 bug — it should
   be automatic, not lucky.
2. **Fail-loud canaries for gate scripts**: "clean" from an enumeration script must
   be distrusted unless the script proves its enumeration was non-trivial (minimum
   row counts, canary symbols that MUST appear, self-test fixtures). The repo has
   this pattern three times already (check-gosec canaries, check-transient-retry,
   release-gates fixtures); check-dead-exports is the fourth and lacks it.
3. **Whole-file writes for small-script rewrites**: three sequential patch edits on
   a 60-line file produced two structural bugs; a single `write` of the intended
   final content plus one diff read would have been both faster and safer.
4. **Verify the attribution story before declaring done**: "the footer commit
   contains my diff" must be checked with `git show --stat`, not assumed from an
   amend's exit code — I did run the check, but only AFTER writing "amend to
   include" prose that turned out wrong.
5. **§-structure reports written from the transcript, not memory**: every incident
   in §d is reconstructable only because the trace/log files were still in /tmp;
   the report was written within minutes of the work, which is the only reason §d1
   is honest instead of forgotten.
