Components (all gate-verified, citations at each claim):

1. **`tq session ping`** (cmd/tq/session.go, help text in cmd/tq/main.go:86-90): appends one `{"id","cwd","last_seen"}` JSON line to the registry. Default id `$CRUSH_SESSION_ID`, default cwd = process cwd, default registry = `$TQ_SESSION_REGISTRY` or `<cache>/tq/session-registry.jsonl`. Touches NO database — only the registry file (hook-budget safe). Refuses an empty id.
2. **Registry mechanics** (internal/session/registry.go): append-only JSONL with single small `O_APPEND` writes (no mid-line interleave on POSIX); load is latest-wins per session id; blank/torn lines are skipped, never fatal; `RewriteRegistry` lets the sweeper prune. File mode 0644, dir 0755 (named constants).
3. **`tq session sweep`**: closes every registry session that is BOTH quiet for `--stale-after` (default 10m) AND unowned (`pgrep -f <id>`), by calling the existing replay-safe `session.Close` — same dedup keys, zero new mint logic. Registry is rewritten without closed ids. Policy pins: a live-crush-owned session is kept; a FRESH session is kept; a FAILED ownership check (e.g. pgrep missing) KEEPS the entry and surfaces the error — the sweeper never closes blind, because closing a live session behind its owner is the exact failure this check exists to prevent.
4. **`scripts/hook-session-registry.sh`**: the PreToolUse hook — best-effort by construction (missing `CRUSH_SESSION_ID` or a failing `tq` exits 0; it can never block a tool call). Wiring into a crush config is OWNER-RUN (contract: I must not edit crush.json/.crushrc — and there is no repo hook config for interactive sessions anyway).
