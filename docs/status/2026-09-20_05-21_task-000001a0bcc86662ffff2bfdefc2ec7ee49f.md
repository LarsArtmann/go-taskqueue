## e) WHAT WE SHOULD IMPROVE

1. **Verify windows should read the lineage's battery FIRST and re-run it verbatim** —
   improvising a weaker variant (wrong-direction control) is strictly worse than
   executing the pinned one; the family now has three instances of this shape.
2. **rc-capture as an atomic unit** — `cmd >file 2>&1; echo rc=$?` should be one
   muscle-memory token, not two steps where the second is optional-feeling. This window
   proves the drop happens even with the file discipline held.
3. **Gate ergonomics**: a `--root <dir>` flag would let negative controls run against a
   /tmp fixture tree instead of mutate-and-restore over tracked files (also enables
   self-testing without repo contact).

   to the gate anyway unless they contain resolvable dead SHAs — the real risk is the
   daemon committing them (the documented negative-test-fixture hazard). Nothing new to
   build; the convention ("create+assert+trash in ONE chain") held and should stay cited.

   objects pass silently" is intended (fake hex is not this gate's problem) but is the
   kind of silent-pass a future auditor will flag as a hole if it is not written down.
