## e) WHAT WE SHOULD IMPROVE

1. **Make footer position a HOOK, not a memory.** The commit-msg hook
   already validates exactly-one well-formed footer; it should also
   reject a footer that is not the last trailer (`git interpret-trailers
   --parse` comparison). This window proves the class fires even when
   the agent knows the rule — the 2026-09-19 incident was blamed on
   scripting, this one on template defaults; a gate kills both.
2. **Pre-work docs: derive topology before writing bookkeeping.** §5
   failed because it reasoned from ADR numbering instead of "where does
   this code actually live" (one rg for the runactor groups would have
   caught it). Rule of thumb: any module-impact section must cite the
   import graph, not the architecture table.
3. **Fold CONTRIBUTING.md into session-start.sh.** The turn-1 ritual
   items that survive are the ones scripted; the attention-dependent
   ones rot (d2 is at least the third documented occurrence).
4. **Template-vs-policy conflicts resolve BEFORE the first commit.**
   When the dispatcher's commit format and repo policy disagree, repo
   policy wins and the message is composed accordingly up front — not
   repaired by amend afterwards (even a clean, unpushed amend is
   avoidable risk + a second `%(trailers)` verification).
5. **Flips need a sunset row for demoted siblings.** When a flip
   promotes one spike module to driver-of-record, the loser (cqrsqlite)
   should get an explicit keep/delete ruling in the same stage —
   otherwise it becomes a ghost module silently costing gates, lint
   baseline rows, and reader attention.
