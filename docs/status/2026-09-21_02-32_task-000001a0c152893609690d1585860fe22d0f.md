## e) WHAT WE SHOULD IMPROVE

- **Split "commit immediately" into two mechanical rules** and follow them
  literally: (1) the code commit fires the moment the in-module
  build+vet+targeted-test passes (seconds) — never wait for the full race
  suite; (2) docs/memory edits get their own immediate add+commit chain,
  right after the last write. Every second between "last write" and "git
  commit" is daemon food, and this window proved even knowing the lesson
  doesn't survive a busy gate queue.

  ritual is manual and its second half (docs/status/README.md rows for the
  task ID) got skipped within hours of being codified. The script already
  greps docs/status/ — adding the index grep makes the defense mechanical.
- **A usage-only derivation helper**: `deriveOutcome` runs the
  Task-Queue-ID trailer scan + diff-tree walk whose Commits/Files both
  review and status executors immediately drop — a wasted `git log` +
  `git diff-tree` per paid review/report run. A `deriveSessionUsage`
  variant (crush-data lookup only) would trim it; tiny cost today, but it
  grows with every usage-only executor (dlqfix uses the closeout-free clone
  too).
- **Batch discipline**: one multiedit call per file; if a call reports
  partial application, re-read BOTH files before the next edit, don't
  reason from the success count.
- **LSP hygiene**: on phantom type errors against a green CLI build, restart
  the LSP immediately instead of re-proving the CLI right.
