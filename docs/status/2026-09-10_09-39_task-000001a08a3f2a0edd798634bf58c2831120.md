2. **`tq show` flag placement is unforgiving** (`tq show ID --db X` fails). Either accept global flags anywhere or document the env-var form in `tq --help`.
3. **The audit had no durable record of WHAT was checked.** The DONE line in TODO_LIST.md summarizes it, but the per-status query results are ephemeral. A `tq doctor --hygiene` (or similar) that encodes this exact check — "no pending agent task carries a verify string matching <known-stale patterns>" — would make the next f46-style audit a gate, not an investigation.
4. **Stale-verify risk is structural, not historical.** The hazard exists whenever a repo's verify contract changes while tasks are queued. Cheaper than auditing: the executor could re-read `.tq-verify` at CLAIM time instead of trusting the enqueue-time pin (or warn on mismatch). That would retire this entire TODO class.
