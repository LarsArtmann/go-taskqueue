## b) PARTIALLY DONE

- **A transiently failed trigger post is LOST for the whole streak (real flaw).** `deadPoolDetector` sets `alerted = true` before calling notify and ignores the post outcome; `NotifyDeadPool` returns an error only on 5xx/transport (4xx is log-and-accept by bridge contract). So a dashboard outage at fire time = the only alert this incident would ever raise is gone until a resolve+re-streak cycle. The code comment ("the next verdict re-sends") is wrong for the trigger case. Correct shape: pass the post outcome back and set `alerted` only when the post was accepted (transient failures then re-fire next tick for free). Found while writing this report; not yet fixed.
- **The cmd/tq glue is untested.** Detector and bridge method are unit-pinned, but the composition (hoisted bridge, notify closure, `observe` call site) has no test: no stub-dashboard e2e proves a blind pool produces exactly one triggered + one resolved ingest through the real `cmdAgentPool` path. The status-loop smoke pattern would carry it.
- **Streak does not survive restart.** A blind pool that restarts faster than N ticks never alerts (state is process-local, like the detector itself). Undocumented; either document or persist (watermark row would fit the house pattern).
- **`--once` mode is a no-op for N ≥ 2.** One tick per process, streak never reaches the default 3. Semantically defensible (short-lived), but a blind once-run is precisely the cron-deployment signal worth alerting on.
- **Discovery-failure blindness is not detected.** When `harvester.Run` itself errors (e.g. dead discovery endpoint) there are no skips to count; the detector only sees per-repo scan failures — the letter of the work item, not the whole dead-pool class.
- **Watch-driven ticks advance the streak faster than `--interval`.** Streak counts RUNS, not wall-clock; undocumented.
- **Live-dashboard verification owed** — inherited debt, now larger: FEATURES already flagged the bridge E2E as stub-only ("live-instance verification still owed"); `NotifyDeadPool` adds a second never-posted-to-a-real-dashboard path.
