## e) WHAT WE SHOULD IMPROVE

- **Adopt the inverted order from edit #1, not after the first hit**:
  last write → `git add <paths> && git commit` with a WELL-FORMED footer
  (Task-Queue-ID LAST trailer, after any attribution block) → gates →
  amend only if gates force changes. Every hour-long verify battery
  loses to a ~2-minute daemon.
- **Fixture-test any git-plumbing tool before touching the real tree**:
  the self-test caught four bugs that a real-tree run would have
  scattered across live history. The fixture cost minutes; a bad
  rewrite on the production lineage costs a heal-of-the-heal.
- **Never hand-roll message/trailer munging**: `git interpret-trailers`
  exists, handles the blank-line placement, existing-trailer, and
  last-trailer-position semantics that the printf version got wrong.
- **Self-test must exist before "done"**: for any script with refusal
  rails, the fixture IS the spec — the prose header lies less after the
  branches have executed.
- **What worked (keep)**: reading the full 09-52/00-27 ruling chain
  before writing a line; building the fixture under /tmp (daemon-food
  rule); running the script-syntax gate early (shellcheck caught the
  unused-var and helper-shape issues); snapshot-based verification
  reasoning written into the code header where the next healer will read
  it; committing before running the multi-minute root battery (only
  followed after the sweep bit — must be default).
