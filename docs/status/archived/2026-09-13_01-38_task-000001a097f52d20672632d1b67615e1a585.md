## a) FULLY DONE

1. **Root cause — the dispatcher is correct, the test's timing assumption was not.**
   `tick()` drains subscribers SEQUENTIALLY in one goroutine
   (internal/consumer/consumer.go:163-167 → `drain` per subscriber). The test
   waited for `healthyDelivered >= 5` and then immediately pinned
   `d.Cursor("flaky") == 1`. But a handler count is observable MID-DRAIN: the
   healthy drain of tick N can finish all 5 facts while the flaky drain of the
   same tick has not started, and under load an entire first tick can still be
   pending. In both windows the flaky cursor legitimately reads 0. Exactly
   matches the incident signature ("cursor = 0", only under load).
2. **Fix (31 insertions, consumer_test.go:179-212)**: gate the cursor pin on
   the pause actually ENGAGING — poll until `flakySeen` contains seq 2 (the
   failing fact attempted). Deterministic because of the drain contract: fact 2
   is only attempted after fact 1 was accepted (Seq order, error stops the
   drain), so cursor is exactly 1 at that moment and cannot advance while the
   handler still fails. `Fatalf` if the deadline passes without any attempt
   (a dispatcher that never reaches the failing fact is still a test failure).
   The `healthy >= 5` poll is kept for the "other subscribers keep flowing" leg.
