## e) WHAT WE SHOULD IMPROVE

- **Make `tq show <task-id>` step one of the ritual when a task id is
  known**: session-start.sh already takes task ids; printing attempts,
  status, lastError head, and requeue NotBefore turns "why am I here"
  from luck into machinery. This window's §d headline becomes impossible
  to miss.
- **Verify-only windows owe a queue-verdict line**: the minimum battery
  should require, next to the repo gates, one line from the task record
  ("attempt N, lastError: none/…"). A DONE-row verdict issued while the
  queue is mid-burn is not a verdict.
- **Close-out batteries should run the TASK's verify command verbatim**
  when the window had budget for it — not a variant with a different
  -timeout. The 02-32 battery ran `-timeout 300s`; the gate wanted 180s;
  the disagreement is exactly where attempt 1 died. Same-command gates
  make inherited citations honest.
- **e2e needs a runtime budget**: TestMain's build + serial subprocess
  scenarios make the package the suite's long pole and the flakiest
  citizen under load (backlog row filed). Trimming or parallelizing it
  protects every future verify, not just this task's.
- **Lease-aware close-out ordering**: when the claimed lease is nearly
  spent, commit the row + report skeleton FIRST, then extend — the
  current order (write everything, commit last) maximizes the chance of
  a mid-write reclaim.
