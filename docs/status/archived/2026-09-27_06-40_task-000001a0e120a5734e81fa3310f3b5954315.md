## §e — WHAT WE SHOULD IMPROVE

1. **Case-semantics divergence is now carried by TWO filters.** sqlite
   `LIKE` is case-insensitive (ASCII default); postgres `LIKE` is
   case-sensitive. `Filter.Query` already had this property; my
   `PayloadContains` inherits it (same `escapeLike`+`LIKE` idiom). The
   conform pin asserts case-insensitivity and passes on sqlite/cqr —
   the same assertion would FAIL on postgres semantics. Either
   normalize (`lower()` both sides or dialect `ILIKE`) inside the
   companion pushdown, or document sqlite-only semantics on the Filter
   fields. One-line-per-frontend fix now; a silent audit false-negative
   class later if postgres ever goes load-bearing.
2. **The daemon-attribution fold should be the DEFAULT, not a maneuver.**
   §d4: every window that lets the daemon sweep code files produces a
   derivation that leans on the folded_here view. The fold is
   sanctioned, documented, and still treated as exceptional. A
   session-start ritual line ("if the daemon committed your work:
   fold into the footer carrier before committing docs") would make the
   clean shape the reflex.
3. **cmd/tq LSP false positives cost attention every window.** gopls
   reported `undefined: truncate/dbFlag/mustOpenDB/resolveDB` and
   `Filter has no field PayloadContains` (module-cache resolution
   against the pinned tag) on every edit — all four pre-existing +
   expected, all confirmed false by the shim gate. AGENTS.md documents
   the templ LSP lie; the cmd/tq module lie deserves the same one-line
   entry so future windows stop re-deriving it.
4. **The audit recipe should be durable, not derivable.** The point of
   §e1 was "stop needing a `tq show` per task" — the one-liner
   (`tq tasks --status pending --type agent --verify-contains '<pattern>'`)
   should live in the AGENTS.md operational contracts so the next
   hygiene audit starts from a recipe (harvested, §f2).
5. **FEATURES.md rot went unnoticed for ~12 days.** The `tq tasks` flag
   cell was truncated mid-list (`--band hot` + abrupt end) since some
   earlier edit — a byte-level check (row cell count / closing pipes)
   would catch table-row amputations mechanically; grep for `| $` or a
   missing final `|` per row is a five-line gate candidate.
