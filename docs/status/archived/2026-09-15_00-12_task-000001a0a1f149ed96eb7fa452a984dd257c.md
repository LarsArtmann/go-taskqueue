## a) FULLY DONE

1. **Projection replay covers all four contract fields**
   (`cmd/tq/journalaudit.go`): `replayProjection` rebuilds per-task state
   from facts alone — status (all transition facts: enqueued/claimed/
   completed/failed/dead-lettered/cancelled/requeued/released), attempts
   (max `Fact.Attempt` over failed/dead-lettered facts, which carry the
   post-increment number; requeue burns nothing), priority
   (`queue.EnqueueDetail.Priority` on `task.enqueued`, superseded by
   `queue.ReprioritizeEvidence.NewPriority` on `task.reprioritized`),
   dedup key (`EnqueueDetail.DedupKey`).
2. **Legacy-fact guards**: RescueDead re-emits `task.enqueued` with only
   `Rescue` set, and pre-detail thin facts carry nothing — both leave the
   projection's `priorityKnown`/`dedupKnown` flags false, so absence of
   evidence is never reported as drift. (The EnqueueDetail doc comment
   literally names priority+dedup as "the inputs of the journal-drift
   audit" — the store side was already prepared.)
3. **Per-field drift report**: `DriftRow` gained a `field` discriminator
   (status | attempts | priority | dedup_key); rows sort by (taskID,
   field); JSON shape extended (`taskId`,`field`,`stored`,`replayed`);
   text output prints one line per diverging field with the advisory
   epilogue (no repair mode, per contract).
4. **Hermetic fixture tests** (`cmd/tq/journalaudit_test.go`): (i)
   full-lifecycle no-drift test over a scratch sqlite store (enqueue ×3,
   complete, dead-letter, cancel — replay must agree exactly); (ii)
   replay-transition unit test incl. attempt max(); (iii) replay
   priority/dedup test incl. reprioritized supersede and the legacy thin
   fact; (iv) `TestJournalDriftSeededDriftAllFields` — seeds drift by
   closing the store, corrupting the `tasks` table with raw
