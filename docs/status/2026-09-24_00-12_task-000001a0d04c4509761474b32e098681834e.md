   the engine finalize succeeds, the adapter runs `UPDATE tasks SET last_error = '' WHERE

   completes; the upstream `queue/sqlite/v4` engine leaves the failed attempt's error on the
   completed row (observable as a stale error in `tq show`/webui). Race-safety argument
   recorded in the code comment: a completed task can never Fail again, so the post-tx clear
   cannot race a new error onto the row. The task allowed "either adapter-side or as the
   upstream fix"; adapter-side is the smallest correct change (an upstream fix needs a
   go-cqrs-lite tag + tq require bump to reach this repo).
