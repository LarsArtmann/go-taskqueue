## e) WHAT WE SHOULD IMPROVE

1. **The closeout TICK-AUDIT convention worked; a COMMIT-AUDIT is missing**
   — nothing mechanical refuses a work commit whose subject doesn't match
   the item, or whose message contains hallucinated trailers (`Closes
   #issue`). A check-commit-message.sh leg could pin: no unresolved
   template markers, footer last line, no `Closes #\w+` in daemon-swept
   subjects.
2. **Evidence-stage classification knowledge lives in three places** (the
   structured stamps, `IsEnvironmentalDeath`'s marker list, and now the
   CLI matcher's alias list) — one shared table in `internal/executor`
   would make the next death class a one-line addition.
3. **`tq dlq` output rows don't show the stage they were filtered by** —
   after `--evidence-stage e2e-timeout` the list looks identical to an
   unfiltered one; an inline `evidence=` suffix (same renderer the webui
   uses) would make the filter self-describing.
4. **Windows cross-compile gate not run for this change** — the cmd/tq
   change is platform-neutral Go, but the convention (`CMD_TQ_OS=windows`)
   was skipped; cheap enough to always run.
5. **The batch's "1 item" framing hid real scope** — the row's two named
   gaps (webui render, worker pin) were part of the item, and honoring
   them stretched a "one filter + one render line" estimate into a
   three-module change. Harvest rows that name gaps should say "item =
   main ask + gaps" explicitly (this one did, in prose — it was nearly
   missed).
6. **Dead tasks' evidence lives only on the failed fact** — `tq dlq`
   filters must do a per-task fact-trail query (O(n) reads). Fine at DLQ
   sizes; if DLQs grow past ~hundreds, a stored-priority-side stage column
   or readmodel surface beats N+1 queries.
