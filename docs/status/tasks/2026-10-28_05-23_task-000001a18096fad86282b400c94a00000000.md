## e) WHAT WE SHOULD IMPROVE

1. **Commit-first, always, in this repo.** Edit → `git add <files> &&
   git commit` → THEN run gates. The daemon's <60s sweep window makes
   test-first ordering a guaranteed race. (AGENTS.md rule existed; I
   knew it and still followed the generic order — the fix is mechanical:
   no gate runs between edit and commit.)
2. **Pre-commit ritual: `git status --short` + `git log --oneline -1` +
   trailer re-read of HEAD before EVERY commit.** Row 117's convention
   (post-commit footer re-read, treat empty as in-flight daemon sweep)
   exists but I applied it only after commit failures. Applied
   pre-commit, it catches the daemon sweep while the heal window is
   maximally open.
3. **heal-daemon-sweep hygiene: audit the span before healing.** For each
   commit in `<from>..HEAD`: `git show --stat` and confirm the files are
   this session's. If any commit carries foreign content, either stop and
   repair it first via commit-tree, or pass `--from <oldest-blocker>` so
   the span excludes it. Never re-run a heal after a manual repair without
   re-auditing — the repaired commit is footer-less again by design and
   WILL be re-folded.
4. **Use `scripts/commit-task.sh` for footed commits** instead of
   hand-rolled heredocs — it enforces the footer-as-final-line shape and
   carries a `--self-test`; hand-rolled messages are how the 2026-10-12
   03-19 incident happened, and I repeated the pattern.
5. **Official gates over hand-rolled invocations**: `scripts/test-cmd-tq.sh`
   exists precisely because cmd/tq's module graph has two legal shapes
   (proxy vs dev.mod shim / go.work). Never `GOWORK=off go test` in
   cmd/tq; the AGENTS.md per-module loop template does not apply there.
6. **Foreign daemon commits are not yours to fold**: preserve their
   message, verify their content builds (I ran root build+vet+vendor-sync
   on the go-health bump), and surface ownership questions (§g Q1)
   instead of silently carrying them inside your span.
7. **Small test-design win worth repeating**: parameterizing the detector
   by path (`TQ_NETNS_DEV_FILE`) let the self-test drive the REAL branch
   logic instead of trusting a stub — stub-only tests would have left the
   `return 2` line unguarded, which is exactly the regression the item
   was about.
