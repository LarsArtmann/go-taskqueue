## e) WHAT WE SHOULD IMPROVE

1. **Test harnesses need false-pass paranoia**: an eval-based fake that silently errors produces the WRONG branch and can still "pass" an assertion (case 1 did). Assert on the die MESSAGE substring, not just rc — the final harness does, keep it that way.
2. **Override-after-source is fragile**: lib redefinition silently beats test fakes. A one-line comment pinning the ordering in the smoke (present) is the minimum; a future `check-*` guard could grep smoke scripts for `source` preceding their overrides.
3. **Offline claims should be provable**: the "offline" test did network I/O for one iteration before the fix. A `unshare -n`-wrapped run (if available in CI) would make the offline claim structural, not aspirational.
4. **The wait loop still polls blind** (pre-existing): §e3's `-w '%{http_code}'` fix would make lag/dead classification HTTP-semantic instead of poke-success-semantic; the new seams make that change trivially testable now.
5. **Die-message duplication**: the two die strings live in the lib; the smoke greps substrings of them. If the strings drift, the smoke fails loudly — good — but the messages are user-facing prose embedded in code; acceptable at this size.
6. **ci-local ordering**: the new smoke sits before `check-script-syntax.sh`; had the shebang been missing, ci-local would have failed at the smoke instead of the dedicated gate. Cosmetic; step order in ci-local is already precedent-driven.
