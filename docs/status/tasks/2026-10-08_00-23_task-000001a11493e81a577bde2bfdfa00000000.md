## e) WHAT WE SHOULD IMPROVE

1. **Never race the daemon for folds**: branch-cut-then-point beats
   reset-soft-fold every time when a BuildFlow hook run is in play (its
   repair phase guarantees mid-operation tree churn → daemon food).
2. **Two goldens, one update flag**: `CQRS_LINT_UPDATE_GOLDEN=1` exists in
   TWO tests (pkg/rules profile + module-root golden). A single wrapper
   (`go generate` or a make-like flake app) that regenerates BOTH would have
   saved the red-module-test round-trip.
3. **Golden absolute paths are a portability landmine**: any test run from a
   worktree/clone fails. Golden should store repo-relative paths (the linter
   could emit relative to ProjectRoot).
4. **Pre-commit hooks that trigger repo-wide repair runs** (dprint/nix-fmt/
   templ-fmt "Repair ran") on a 300-module monorepo create 500-file churn
   waves that then feed the daemon. Repair should be scoped to staged files
   or behind an explicit `--fix` in this repo.
5. **Verify-before-editing discipline held up**: re-deriving the three
   rulings' evidence from primary sources (instead of trusting September
   reports) caught that V006 was already fixed — writing a third fix would
   have been pure fiction. Keep: verify the TODO row's premise at pickup,
   exactly as O9 rules.
6. **The dq on the checked-out branch name**: I named the working branch
   `…scoped-fixes` and the clean one `…-review`. Confusing pair. One branch,
   clean, named once.
