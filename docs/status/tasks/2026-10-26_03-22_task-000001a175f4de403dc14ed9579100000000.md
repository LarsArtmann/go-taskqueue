## e) WHAT WE SHOULD IMPROVE

1. **Commit-atomic editing under the daemon**: the repo's own rule
   "stage+commit BEFORE running anything" is necessary but insufficient —
   the daemon restores unstaged edits within seconds. The working pattern
   (write + `git add` + commit in one process) should be the documented
   default for multi-file script edits; a tiny helper would remove the
   per-session improvisation.
2. **heal-daemon-sweep `--from` semantics**: document the exclusive base
   bound in --help, and consider preserving original subjects on commits
   that ALREADY carry a footer (retitle should apply to footer-less
   commits only).
3. **Pre-push guard should walk history** (§b1) — tip-only inspection is
   a designed-in blind spot; fix before trusting the guard.
4. **Hook liveness probe**: session-start already warns on missing
   commit-msg/pre-commit; extend it to pre-push and to staleness vs the
   installer's bytes (a missing hook = the c7e95833 class recurs
   silently).
5. **TOCTOU honesty**: the age check passes and THEN the push proceeds —
   a commit can cross the age boundary between check and transfer. Fine
   for the 10-minute scale, but the escape hatch (--no-verify) should be
   documented as the sanctioned override, not a workaround.
6. **TQ_PUSH_MIN_AGE ergonomics**: 600s will refuse legitimate fast
   operator pushes of fresh daemon chores; the refusal text covers the
   escape, but a `--why <sha>` dry-run mode would make triage one
   command.
7. **--no-verify discipline**: reserve for hook-broken situations;
   default to running the hooks and reading the failure.
