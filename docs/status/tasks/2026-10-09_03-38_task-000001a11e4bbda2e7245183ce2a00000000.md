## e) WHAT WE SHOULD IMPROVE

1. **The 03-11 smoke's constant-code-per-case design is exactly why this bug shipped**: each
   fake set ONE code for all attempts, so stale-code reads were invisible. Lesson generalizes:
   a smoke that pins a seam to a CONSTANT cannot catch ordering/staleness bugs in the code
   under test — varying-the-seam-across-attempts cases should be the default for any loop
   with carry-over state. Worth a lesson note in the repo (this report is the record).
2. **Reviewer's simulation harness beat my reading**: the finding cited "verified by running
   the loop with faked seams" — the smoke now encodes that verification permanently (two
   varying-code cases), which is the right place for it.
3. **`|| rc=$?` capture pattern**: `if tq_proxy_poke …` cannot coexist with reading state the
   callee set, under `set -e`, without the rc-capture form. This is the second bash seam in
   scripts/lib to need it; if a third appears, a one-line convention note in AGENTS.md
   (session shell hazards section) would save the next agent a red run.
4. **Die-message wording**: "every .info poke succeeded" is now subtly inaccurate — it means
   "the LAST poke succeeded/404". The strings are already rowed for constants-sharing (TODO
   die-message row); the wording fix should ride that row, not mint a new one.
5. **My patch discipline**: three red smoke runs for a 6-line diff is a personal-worst ratio.
   Rule for next time: when a finding states the expected direction verbatim, the first patch
   IS that direction — no creative intermediate shapes.
