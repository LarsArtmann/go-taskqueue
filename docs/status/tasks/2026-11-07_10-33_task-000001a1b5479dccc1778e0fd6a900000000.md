   compiles, not after docs+ticks accumulate — the 10-15-minute

   commit-before-gate advisory catches gates, not edits.
2. **`check-prompt-const-folds.sh` scope**: it passed at commit time
   because the sweep landed SECONDS later — the guard scans
   origin/master..HEAD at run time, so it cannot catch a sweep that
   lands between the check and the push. A push-time (or ci-local)
   re-run would close the window.
3. **`tq tasks --json` machine-face wart** (noticed in passing during
   item 4): an empty filter prints `null` instead of `[]` — JSON
   consumers must special-case it. `tq dlq --json` gets this right
   (summary object). Worth pinning `[]`.
4. **New sweeper has no liveness coverage**: `internal/docsgates` is
   timer-driven like every mint pass, but the frozen-sweepers /
   dead-sweepers detection family (pool-health, worker-death detector)
   doesn't know about the `docsgates-bridge` cursor — a bridge whose
   ticks stand still while repos rot is invisible.
5. **cmd/tq proxy-build gap** (known accepted state, now concrete):
   cmd/tq's committed go.mod requires root v0.4.1, which predates
   `internal/docsgates` — GOWORK=off builds fail at HEAD until the
   next root release. The docs-gates stale-binary lesson applies to
   the future provider too; the release wave should land soon.
6. **Bridge prompt rails**: the minted fix prompt forbids weakening
   `.docs-gates.json` to go green, but nothing ENFORCES it (a fix
   agent could still narrow a threshold and pass `docs-gates run .`).
   A mint-side guard (verify re-checks the config unchanged) would
   make the rails real.
