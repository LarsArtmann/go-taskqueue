## d) TOTALLY FUCKED UP

1. **The eval-based hook contract was broken at birth.** First draft
   invoked self-test hooks as `eval "$CMD" arg1 arg2 arg3`, which
   SPLICES the args into the hook text — the `exit 0` fixture became
   `exit 0 <module> <version> <dir>` → "exit: too many arguments", rc
   garbage, counters frozen at 0/0/0. Battery A failed on the very first
   self-test run. Fix: hooks run under `bash -c "$CMD" label args…`
   (clean positionals, fixture owns its exit). Lesson: hermetic hook
   fixtures must own their control flow; never let the harness append
   args into eval'd text.
2. **I theorized for four tool calls before instrumenting.** The 0/0/0
   summary made no sense under my mental model of `exit`-with-extra-args;
   I ran hypothesis tests (`bash -c`, heredoc bashes) that each explained
   HALF the evidence. The `set -x` trace on a /tmp copy identified the
   real flow in one shot. Lesson (a repeat repo lesson): observe first,
   theorize second — the Observe-first convention exists precisely for
   this and I under-applied it inside my own debugging.
3. **`*task*` matched every facade.** The battery-C fixture glob
   `*task*` matches ALL module paths because the parent module is
   literally `go-taskqueue` — all five facades resolved as task and the
   counters read 0/4/1 with five FAILs naming task@v9.9.9. The self-test
   pin CAUGHT it (the pins did their job), but writing `*/task` (the
   facade segment is the last path component) was obvious in hindsight.
4. **Swallowed `go get` stderr** (`>/dev/null 2>&1`) turned a
   self-explanatory DNS timeout into a bare "not a known dependency" —
   cost one extra diagnose round during the real-run validation. Fixed
   to `>/dev/null` (stdout only). Lesson: in a gate whose SKIP-vs-FAIL
   semantics hinge on WHY resolution failed, stderr is the receipt.
5. **Commit→amend churn produced a duplicate commit I misread as
   success.** I committed before the self-test was fully green (the
   commit-before-gate ordering rule), then amended twice more (fixture
   fix, stderr fix, CHANGELOG row). The second amend silently created a
   NEW commit (`3a2a34cd`) instead of amending; commit-task printed
   "FAIL: committed, but named file(s) absent from the resulting commit"
   and I treated it as the expected idempotent-re-run noise. Only the
   `git log --oneline -3` check two calls later exposed two stacked
   same-subject commits; fixed with `git reset --soft` + one
   commit-task. Lesson: read the FULL commit-task output — its FAIL
   lines describe history shape, and "one commit per item" needs the
   post-commit `git log` re-read the AGENTS footer-attribution rule
   already mandates (I ran it for the footer but not for the SHA
