## a) FULLY DONE

1. **Root cause traced.** The reclaim path itself is sound:
   `ClaimDue` reclaims an expired lease and records `task.released` with
   `Effect: unknown` (`internal/queue/companion/claims.go:199-204`), and
   the lease-lost worker discards its attempt without failing
   (`internal/worker/worker.go:732-738`). The completion came from the
   claim-time `DonePreflight` gate: signal 1 (`footerCommitExists`,
   `internal/harvest/donepreflight.go`) completed on ANY commit carrying
   the task's `Task-Queue-ID` footer — the reclaiming claim hit member 1's
   footed commit and completed the whole 3-item batch with
   `preflight_done` detail 84 ms after claim. Signals 2-4 were never
   reached; the batch-aware all-stale semantics already existed for
   signal 3 only.
2. **Mechanics decided and implemented** (commit `475f1af2`): the
   footer signal is now batch-aware — for a MULTI-member batch it
   completes only when every member key is ticked-or-gone (reusing
   signal 3's `itemStale` prune-parity rules via new helper
   `batchHasOpenMembers`); a partially-landed batch falls through, the
   later signals (fix-cure / all-stale / closeout report) may still
   complete it, and the default is a re-run over the open members.
   Single-key tasks unchanged (the footer IS the full-work proof for
   them). Chosen over re-enqueue-unlanded-keys because the not-done
   verdict reuses the existing claim/attempt ladder with zero new
   machinery; the gate-slow done guard (`worker.go:822`) inherits the
   fix for free (same hook).
3. **Pinned by two test batteries**:
   - `TestDonePreflightBatchFooterRequiresAllMembersLanded`
     (internal/harvest/donepreflight_test.go): 3 cases — partial members
     open (the exact 1/3 incident shape → not done), every member ticked
     (→ done via footer), every member gone (→ done).
   - `TestDonePreflightAfterLeaseReclaimCompletesWithoutRerun`
     (internal/worker/worker_test.go): end-to-end lease-expiry reclaim —
     executor outlives the 80 ms lease, returns `LeaseLostError`; asserts
     the `task.released` fact exists with `EffectUnknown` ("crashes aren't
     finishes"), the reclaiming claim's done verdict completes WITHOUT a
     second executor run, and status is completed. This is the incident's
     mechanism, now visible and gated.
