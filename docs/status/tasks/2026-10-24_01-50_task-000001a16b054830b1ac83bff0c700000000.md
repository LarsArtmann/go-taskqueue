## e) WHAT WE SHOULD IMPROVE!

1. **Commit-first, always**: the §d3 race is a direct, documented
   consequence of skipping stage+commit before running batteries. The
   ordering contract exists precisely because multi-minute battery runs
   are daemon food. Next window: stage the work commit BEFORE any gate
   run, tick TODO rows in the same commit.
2. **Assertions must be proven against real output shapes**: two of my
   first-draft pins failed on live output (pretty-printed JSON spacing;
   FAIL-line text matching the grepped substring). Both were caught by
   running the thing — good — but the faster discipline is: capture a
   REAL output sample, write the pin against the sample, then run. Cheap
   probe binaries (`build-tq.sh` to /tmp) made this easy for `tasks
   --json` shape; do it before writing assertions, not after a red run.
3. **Self-test hooks should degrade, never abort the host control**: the
   first exact-count setup hard-FAILed inside the rc=127 negative-control
   extract (no sibling enumerator there), breaking the control. Rule
   learned and encoded: setup for a pinned case must be guarded so a
   relocated self-copy still reaches the branch the control exists to
   prove.
4. **Red-tolerant self-tests are a two-edged pin**: they keep the summary
   pins green while the fleet is red (correct — the reds have their own
   owners), but nothing forces the reds closed. §f1/§f2 carry them.
5. **Fixture realism details matter**: the go-mods battery needed the
   require in BLOCK form (the grep is anchored to module-path-at-line-
   start) and a PRERELEASE version (the pinned-require filter accepts
   `v0.0.0` as a "real tag" — see §f3, a genuine gate blind spot this
   window surfaced in passing).
