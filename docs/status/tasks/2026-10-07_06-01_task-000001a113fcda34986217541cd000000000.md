## e) WHAT WE SHOULD IMPROVE

1. **Re-anchor before concluding**: `git log --oneline -3` +
   `git status --short` immediately before ANY tree-fact conclusion in
   a multi-agent forest. Facts expire; the diff you act on must be
   younger than the last sweep.
2. **rc-to-file from command one**: the FIRST rc capture of a window
   should follow the battery discipline (redirect, append rc, read the
   file), not a piped echo. Pipes in rc capture are the documented
   PIPESTATUS trap and it bites on command one.
3. **Run the gate once, triage from the log**: the verify gate is one
   command; I spent four rounds (build, vet, test, gofmt) where one
   captured log would have shown all three breakages at once and let me
   repair in a single pass.
4. **Classify before grepping**: when the brief already shows fresh
   daemon commits touching the failing packages, correlate commits →
   suspect sweep-state FIRST (vendor staleness, mid-format files), and
   only then read error text. This window's breakages were both
   sweep-state classes.
5. **The gate classifier earns its keep**: attempt 2's
   "pre-existing/environmental (gate also fails at the pre-attempt
   rev)" verdict was exactly right and is the only reason attempt 3
   inherited a diagnosis instead of a mystery. Worth protecting that
   classification path from future simplification.
