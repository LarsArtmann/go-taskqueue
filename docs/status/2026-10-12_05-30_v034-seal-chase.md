## e) What we should improve

1. **Quiet-tree precondition for seal-grade runs.** Sixteen rounds; at
   least five were burned racing the sibling's landings. A wrapper that
   waits for HEAD stability (e.g. 120 s) before ci-local would convert
   noise into waiting.
2. **ci-local runs sections to completion and reports a combined verdict.**
   Early-abort (lint-baseline → dead-sha → smokes) meant each round
   exposed exactly ONE new red; the same information was available in
   round 7. (Self-test FAIL prints inside section output also read as
   gate verdicts — label them "self-test: EXPECTED FAIL" in the fixture.)
3. **The daemon-race SHA class needs a systemic cure, not per-report
   archaeology.** Seven fork-records + 102 baselined tokens this window;
   every healed closeout accretes more. Ideas: heal-daemon-sweep could
   stamp a `Rewrites: old→new` trailer that the gate auto-reads; or
   closeout prompts could refuse pre-heal SHAs.
4. **`golangci-lint cache clean` on /mnt/buildcache is broken** under
   concurrency (unlinkat directory-not-empty). Either per-session cache
   dirs by default for regens, or a health check + auto-fallback.
5. **Smoke suite vs shipped-behavior drift has no canary.** Three smokes
   were stale against deliberate features (docs-only skip, batched
   harvest default). A tiny "smoke expectations vs feature flags" checklist
   in the feature closeout prompt (did a default change? did a classifier
   change?) would catch these at feature time, not seal time.
6. **The `go install pkg@ver` sandbox ban** is reasonable, but the session
   needs a sanctioned one-liner for release proofs — download+build works;
   document it next to RELEASE.md's proxy-proof step.
7. **Twin constants** (Go test ↔ bash gate) should be one sourced value:
   a tiny `scripts/lib/agents-budget.txt` both read would have made my
   partial reset impossible.
8. **rc hygiene in chained background commands**: my `&&`-chain rc
   mislabeling argues for always writing rc to a named file per command
   (the repo already has this rule for batteries; I violated its spirit
   inline).
