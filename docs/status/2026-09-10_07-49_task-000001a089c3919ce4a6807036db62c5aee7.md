## e) WHAT WE SHOULD IMPROVE

1. **Dry-run any scripted history edit before running it.** Test the editor
   against the actual message text (`git log -1 --format=%B | <your sed>`)
   BEFORE the rebase. After the failed pass I ran exactly this check and it
   matched — proving the editor had never been invoked. That check costs one
   command and would have saved a full rewrite.
2. **Use script files, not inline quoted commands, for git's editor hooks** in
   this environment. `GIT_EDITOR=/tmp/foo.sh` worked where
   `GIT_EDITOR="sed -i 's/…/…/'"` silently failed.
3. **Verify by path, not by phrase.** `git log -1 -- <path>` is unambiguous;
   `--grep` matches any commit whose message mentions the words.
4. **Re-check `git status` immediately before every state-sensitive git
   operation.** The daemon commits between calls — observed twice this
   session. Assumptions about the tree aged in seconds.
5. **Count the replay.** `Rebasing (N/N)` is a free integrity check: N should
   equal the commits you counted under the range. A mismatch means the world
   moved mid-flight — stop and reconcile before continuing.
6. **Codify the footer contract mechanically** (§c1): a commit-msg hook in
   `scripts/install-pre-commit.sh` beats reviewer eyeballs. Cheap, local, and
   it would have prevented this entire finding.
7. **Treat "same ID everywhere" as a data-integrity invariant, not a formality.**
   The f26 cluster now has three IDs across five artifacts; every future
   archaeologist pays for that. When a prompt hands you an ID, stamp exactly
   that ID, and if a second ID appears mid-task (as the reviewer's did), ask
   why before propagating either.
8. **Keep the nix gate out of scope when the tree contains another agent's
   in-flight work** — but say so explicitly in the report (done, §a4), because
   "gates green" claims that silently skip a gate are how false confidence
   spreads.
